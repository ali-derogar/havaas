# حواس — سامانهٔ تمرین توجه و حافظه

سامانهٔ فارسی یک مرکز درمانی با حساب مدیر، درمانگران و والدین. هفت بازی، ارزیابی اولیه، سطح‌بندی تطبیقی، پرونده و گزارش روی سرور مشترک اجرا می‌شوند. رابط با JavaScript و SVG محلی، سرور با Node.js 24 و Express 5 و ذخیره‌سازی با PostgreSQL 18 ساخته شده است.

نگاشت بندهای پروپوزال به مسیرهای قابل‌استفاده و آزمون‌های پذیرش در [راهنمای پذیرش پروپوزال](docs/proposal-acceptance.md) آمده است. `npm run test:proposal` تمام ۲۶ حالت و ۱۰۴ اجرای ارزیابی/سطح را با اعتبارسنجی سرور بررسی می‌کند.

## اجرای Docker و ساخت نخستین مدیر

Docker و Docker Compose لازم‌اند. برای ساخت تنظیمات، Node.js 24 روی میزبان کافی است:

```sh
npm run setup:env
docker compose up -d --build --wait
docker compose exec app npm run admin:create
```

فرمان اول `.env` را با رمز پایگاه داده و کلید نشست تصادفی و دسترسی فایل 0600 می‌سازد؛ فایل موجود را بازنویسی نمی‌کند. فرمان سوم ایمیل، نام و رمز نخستین مدیر را می‌پرسد؛ رمز هنگام تایپ نمایش داده نمی‌شود. حساب یا رمز پیش‌فرض وجود ندارد. در اجرای غیرتعاملی، همین فرمان JSON شامل `email`، `name` و `password` را از stdin می‌خواند؛ رمز را در آرگومان خط فرمان قرار ندهید.

برنامه به‌طور پیش‌فرض در **http://localhost:4173** است؛ پورت و نشانی با `APP_PORT` و `APP_ORIGIN` در `.env` تغییر می‌کنند. `GET /health` سلامت پایگاه داده را نیز بررسی می‌کند. مدیر از «حساب و دسترسی‌ها» درمانگر دعوت می‌کند؛ پس از پذیرش دعوت، درمانگر پرونده می‌سازد و والد را به همان پرونده دعوت می‌کند.

لینک دعوت ۴۸ ساعت و لینک بازیابی رمز ۳۰ دقیقه اعتبار دارد و یک‌بارمصرف است. ارسال لینک دستی است و سرویس ایمیل لازم نیست. برای اتصال یک والد دارای حساب به پروندهٔ دیگر، همان والد باید ابتدا با حساب موجود خودش وارد شود؛ دعوت، رمز حساب موجود را تغییر نمی‌دهد.

اگر تنها مدیر رمز خود را فراموش کرده باشد، اپراتور سرور می‌تواند لینک بازیابی موقت بسازد:

```sh
docker compose exec app npm run admin:reset-link
```

## استقرار HTTPS

برای دامنه‌ای که به سرور متصل است، `DOMAIN` را در `.env` قرار دهید و اجرا کنید:

```sh
docker compose -f compose.yaml -f compose.production.yaml up -d --build --wait
```

Caddy گواهی HTTPS و پراکسی را فراهم می‌کند؛ پورت برنامه مستقیماً منتشر نمی‌شود. در این حالت کوکی نشست `Secure` است و برنامه هدر پراکسی را از Caddy می‌پذیرد. نسخهٔ عادی Compose برای آزمایش محلی HTTP تنظیم شده است. پایگاه داده در تنظیمات پایه و تولیدی پورت عمومی ندارد. هیچ سرویس یا دامنهٔ عمومی در این پروژه خودکار منتشر نمی‌شود.

## دسترسی‌ها

- مدیر: مدیریت کاربران، دعوت درمانگر، مشاهده و مدیریت همهٔ پرونده‌ها، تعیین درمانگر مسئول، انتقال داده و بازیابی حساب.
- درمانگر: پرونده‌های تحت مسئولیت خودش، دعوت و قطع دسترسی والد همان پرونده، ارزیابی، تمرین، تنظیم سطح و خروجی دادهٔ خام.
- والد: فقط فرزندان متصل به حساب خودش؛ اجرای ارزیابی و تمرین با تنظیم تعیین‌شده، گزارش پیشرفت و چاپ یا PDF. یادداشت بالینی، ویرایش پرونده، مدیریت دسترسی، تغییر سطح و خروجی JSON/CSV خام در اختیار والد نیست.

هر پرونده یک درمانگر مسئول دارد. یک والد می‌تواند چند فرزند و یک کودک چند والد متصل داشته باشد. مجوزها روی همهٔ APIها بررسی می‌شوند؛ مخفی‌کردن دکمه‌ها جای کنترل سرور را نمی‌گیرد. خروج از حساب، غیرفعال‌شدن کاربر یا تغییر رمز، دسترسی نشست‌های نامعتبر را قطع می‌کند.

رمزها با `scrypt`، نمک تصادفی مستقل و `N=131072, r=8, p=1` ذخیره می‌شوند. دادهٔ نشست در PostgreSQL و فقط شناسهٔ نشست در کوکی `HttpOnly` و `SameSite=Lax` است؛ نشست هشت ساعت اعتبار دارد. درخواست‌های تغییردهنده به توکن CSRF نیاز دارند و Origin خارجی رد می‌شود. ورود و پذیرش دعوت محدودیت تعداد تلاش دارند. کلیدهای دعوت فقط به شکل هش در پایگاه داده هستند.

## پرونده، ارزیابی و تعیین سطح

نام، نام خانوادگی، تاریخ تولد، پایه، مدرسه و مشکلات احتمالی ثبت می‌شوند. مشکلات اختیاری‌اند. تاریخ تولد ورودی میلادی و تاریخ‌های گزارش شمسی هستند. ویرایش و حذف پرونده فقط برای مدیر و درمانگر مسئول است؛ حذف با تأیید صریح رابط انجام می‌شود.

«ارزیابی اولیهٔ هفت بازی» برای هر مؤلفه پنج تمرین در سطح آسان اجرا می‌کند. هر بخش پس از پایان ذخیره می‌شود؛ می‌توان بین بخش‌ها استراحت کرد و از دستگاه دیگری ادامه داد. بازیِ نیمه‌تمام از وسط محرک بازسازی نمی‌شود؛ بخش تکمیل‌نشده از ابتدا اجرا می‌شود. ارزیابی حالت‌های دیگر، مانند اعداد، تابلوها و جست‌وجوی دوهدفه، از راهنمای همان بازی در دسترس است.

پیش از هر اجرا، صفحهٔ آمادگی هدف و روش پاسخ را توضیح می‌دهد؛ پس از دکمهٔ «آماده‌ام»، شمارش معکوس سه‌ثانیه‌ای اجرا می‌شود. این دو بخش از زمان بازی حذف می‌شوند. شمارش معکوس هم با توقف یا رفتن به زبانهٔ دیگر متوقف می‌شود.

در پنج تمرین اولیه، پس از هر تصمیم یا دور، بازی برای مرور پاسخ می‌ایستد. دلیل هدف‌بودن یا نبودن، نیاز وسیله و مرجع دقیق حافظهٔ فعال نشان داده می‌شود؛ تمرین بعد فقط با درخواست کودک شروع می‌شود. این توقف‌ها در امتیاز و زمان واکنش وارد نمی‌شوند. بازی اصلی پیوسته است و مرجع حافظه را نشان نمی‌دهد. نتیجه و تنظیم شروع، روش بازخورد (`feedbackMode`) را ثبت می‌کنند.

نمونه‌های تعاملی بدون زمان، بخشی از امتیاز ارزیابی نیستند. استروپ برای هر چهار قانون نمونهٔ پاسخ‌دادن و پاسخ‌ندادن دارد. حافظهٔ فعال، مرجع یک، دو یا سه محرک قبل را برای شکل، عدد یا اسباب‌بازی آموزش می‌دهد. تمرین آموزشیِ تکراری که ارزیابی نیست، نتیجه یا تغییر سطح ایجاد نمی‌کند.

سطح برای هر «کودک، بازی، حالت و نسخهٔ پروتکل» مستقل ذخیره می‌شود. در روش تطبیقی، نتیجهٔ ارزیابی سطح شروع را تعیین می‌کند و پایان هر جلسهٔ اصلی معتبر حداکثر یک سطح تغییر ایجاد می‌کند. درمانگر با انتخاب سطح، روش را ثابت می‌کند؛ دکمهٔ فعال‌کردن سطح تطبیقی دوباره تغییر خودکار را فعال می‌کند. والد امکان تغییر ندارد. تنظیم جلسه هنگام شروع روی سرور ثبت می‌شود؛ تغییر درمانگر در حین بازی فقط به جلسهٔ بعد اعمال می‌شود.

قواعد فعلی `src/core/reports.js`:

- افزایش: حداقل پنج تصمیم، تشخیص حداقل ۸۵٪ هدف‌ها، دقت حداقل ۹۰٪، انتخاب غلط حداکثر ۱۰٪، زنجیرهٔ درست حداقل `min(10, تعداد تصمیم‌ها)` و میانگین پاسخ حداکثر ۶۵۰ میلی‌ثانیه در بازی واکنشی، ۵ ثانیه در جست‌وجو و ۶ ثانیه در ماجراجویی.
- کاهش: تشخیص کمتر از ۶۰٪ هدف‌ها، دقت کمتر از ۶۵٪، خطای انتخاب بیشتر از ۲۵٪ یا تکمیل‌نشدن مأموریت.
- در سایر شرایط سطح حفظ می‌شود؛ حداقل آسان و حداکثر سخت است.

ثبت نتیجه و تغییر سطح یک تراکنش هستند. ارسال دوبارهٔ نتیجه به همان شناسه، رکورد جدید نمی‌سازد. دو جلسهٔ هم‌زمان با یک بازبینی تنظیمات، سطح را دوبار تغییر نمی‌دهند. آستانه‌ها قواعد اجرایی این نسخه‌اند؛ پروپوزال عدد دقیق آن‌ها را تعیین نکرده و گزارش، تشخیص پزشکی یا ارزیابی استاندارد بالینی نیست.

## تجربهٔ بازی

در صفحهٔ بازی، منوهای پرونده و گزارش کنار می‌روند تا هدف، زمان و دکمهٔ پاسخ فضای کافی روی موبایل داشته باشند. توقف، صدا و خروج از مسیر توقف در دسترس‌اند. پاسخ واکنشی با پایین‌رفتن انگشت یا ماوس ثبت می‌شود؛ کلیک دیرهنگامِ حاصل از رهاکردن همان فشار نمی‌تواند نوبت بعد را پاسخ دهد.

آموزش شکار دوهدفه هر دو رنگ را آموزش می‌دهد. جست‌وجو نمونهٔ تعاملیِ تطبیق دقیق و سپس نمونهٔ حفظ و پنهان‌کردنِ بدون زمان دارد؛ درخواست دیدن دوبارهٔ نمونه فقط در آموزش مجاز است. حین جست‌وجوی اصلی، نشانگر هدف فقط نمونه‌ای را نشان می‌دهد که قبلاً پیدا شده؛ هدف باقی‌مانده پنهان می‌ماند.

در سفر، برداشتن وسیله جای آن را با علامت کوله مشخص می‌کند و کنارزدن مانع بازخورد کوتاه دارد. پس از پایان، تصویر حرکت کشتی یا پرتاب سفینه نمایش داده می‌شود؛ انیمیشن از زمان امتیازدار جداست و تنظیم کاهش حرکت دستگاه را رعایت می‌کند. مرور اختیاری نتیجه، حداکثر چهار اشتباه یا دور متفاوت را با نمونهٔ واقعی توضیح می‌دهد؛ در حافظهٔ فعال، مرجع همان نوبت نشان داده می‌شود. مرور هیچ امتیاز یا نتیجهٔ تازه‌ای ثبت نمی‌کند.

ترسیم تازهٔ شکار و سفرها با `stimulusVersion=2` از ترسیم قبلی در نمودار جدا می‌شود. آستانه‌های سطح و قواعد شمارش نوبت‌ها تغییر نکرده‌اند.

## قواعد هفت بازی

- **شکار هدفمند:** ستاره، شکل هندسی، ماهی، پروانه و پرنده؛ یک یا دو نمونهٔ هدف. آسان/متوسط/سخت، ۳/۵/۷ شکل هم‌زمان با افزایش شباهت و تغییر اندازه، مکان و پس‌زمینهٔ آشنا یا ناآشنا دارند. فقط هدف دقیق امتیاز می‌گیرد؛ انتخاب مزاحم در حضور هدف هم خطاست. بلوک‌های ۲۰، ۵۰ و ۸۰ نوبتی، زمان توجه پیوسته را افزایش می‌دهند.
- **کشتی نوح:** انتخاب وسایل ضروری از اشیای ساحل و سوارشدن پیش از پایان زمان. سطح‌ها ۴/۵/۶ وسیلهٔ لازم، ۱۲/۱۸/۲۴ شیء و ۶۰/۴۵/۳۰ ثانیه دارند. داستان سفر با سطح تغییر می‌کند؛ فهرست نیازهای سفر با جمع‌آوری وسیلهٔ مربوط تیک می‌خورد و کاربرد وسایل در بازخورد توضیح داده می‌شود. ده ثانیهٔ پایانی و آماده‌بودن وسیلهٔ نقلیه مشخص‌اند.
- **سفینهٔ فضایی:** تجهیزات سفر، موانع و خروج به‌موقع. ۲/۳/۴ وسیلهٔ ضروری حتماً پشت مانع هستند؛ موفقیت به کنارزدن موانع، تکمیل تجهیزات و پرتاب نیاز دارد.
- **چراغ راهنمایی:** پاسخ به سبز و خودداری از قرمز؛ حالت تابلوها، پاسخ به یک‌طرفه و خودداری از ورود ممنوع است.
- **بگرد و پیدا کن:** دو ثانیه حفظ نمونه و ده دور جست‌وجو، با شکل یا حروف دارای خط‌های کوچک، منظم یا پراکنده. حروف و خط‌های متصل، برداری و مستقل از فونت دستگاه‌اند (`stimulusVersion=2` برای حروف). شمارندهٔ حفظ نمونه دو ثانیه را نشان می‌دهد و نمونهٔ دور تازه در محدودهٔ دید قرار می‌گیرد. حالت دوهدفه نیاز به حفظ و پیدا‌کردن هر دو هدف در همان دور دارد. هر کشف یک امتیاز؛ انتخاب تکراری امتیاز ندارد. پایان زمان فقط هدف‌های پیدانشده را خطای حذف ثبت می‌کند. سقف بازی اصلی تک‌هدفه ۱۰ و دوهدفه ۲۰ است.
- **حواستو جمع کن:** تطبیق با یک، دو یا سه محرک قبل با شکل، عدد یا اسباب‌بازی. محرک‌های گرم‌کردن خارج از امتیازند و تطبیق ناخواسته تولید نمی‌شود.
- **استروپ:** دایرهٔ زرد، رنگ نوشته، معنای نوشته و هم‌زمان رنگ و معنا. چهار بلوک ۴۰، ۴۰، ۴۰ و ۳۰ نوبتی با توقف زمان و مثال پاسخ‌دادن و پاسخ‌ندادن برای هر قانون تازه؛ نشانگر مرحله، قانون فعلی را مشخص می‌کند.

در بازی‌های واکنشی اصلی، ۱۵۰ نوبت و ۳۰ نوبت هدف وجود دارد؛ فاصلهٔ آغاز نوبت‌ها یک ثانیه و نمایش آسان/متوسط/سخت ۳۰۰/۲۰۰/۱۰۰ میلی‌ثانیه است. مزاحم‌های هم‌زمان شکار، زمینهٔ همان نوبت‌اند. جست‌وجو ده دور و ماجراجویی‌ها مأموریت زمان‌دار دارند. در آموزش پنج‌تمرینی واکنشی، دو نمونهٔ هدف برای آموزش وجود دارد.

پاسخ با لمس محرک، دکمهٔ ثابت یا کلید فاصله ثبت می‌شود. پس از ناپدیدشدن محرک، دکمه تا شروع نوبت بعد فعال می‌ماند. پاسخ تکراری پذیرفته نمی‌شود. زمان توقف و ساخت رابط از زمان فعال و فرصت نمایش یا جست‌وجو کم نمی‌کنند.

امتیاز واکنشی، هدف درست منهای انتخاب غلط با حداقل صفر است. امتیاز جست‌وجو تعداد کشف و امتیاز سفر تعداد وسایل ضروری جمع‌شده است. انتخاب غیرضروری در سفر یک‌بار دو ثانیه جریمه دارد. جمع‌آوری همهٔ وسایل بدون خروج به‌موقع، موفقیت و ستارهٔ تکمیل نیست.

## ثبت نتیجه و گزارش

سرور هنگام شروع، شناسه، اجراکننده، سطح، نسخهٔ پروتکل و بذر تولید محرک‌ها را ثبت می‌کند. هنگام پایان، پاسخ‌ها با محرک‌ها و گزینه‌های همان جلسه اعتبارسنجی و امتیاز، خطاها، زنجیره و میانگین دوباره محاسبه می‌شوند؛ عدد امتیاز ارسالی مرورگر قابل اعتماد تلقی نمی‌شود. حداقل مدت و فاصلهٔ نوبت‌های واکنشی، زمان حفظ نمونه و مهلت جست‌وجو، ترتیب رویدادهای سفر و پایان مأموریت نیز بررسی می‌شوند. زمان انتخاب سفر از فاصلهٔ پاسخ‌ها یا کناررفتن مانع دوباره محاسبه می‌شود؛ نتیجهٔ نامعتبر، سطح را تغییر نمی‌دهد.

بازی پس از تأیید شروع از سرور آغاز می‌شود. قطع ارتباط در حین بازی جلوی تکمیل آن را نمی‌گیرد. نتیجه تا تأیید ذخیره در حافظهٔ صفحه می‌ماند، دکمهٔ تلاش مجدد و ورود دوباره دارد و خروج از صفحه هشدار داده می‌شود. تا قبل از تأیید، پیام «ذخیره شد» نشان داده نمی‌شود. بستن کامل صفحه پیش از ذخیره ممکن است نتیجهٔ ارسال‌نشده را از بین ببرد؛ صف آفلاین دائمی ساخته نشده است.

گزارش شامل پاسخ درست، غلط، بدون پاسخ، زمان فعال، میانگین واکنش، زنجیره، نقاط قوت و پیشنهاد تمرین است. درمانگر جزئیات محرک و پاسخ، تجهیزات جمع‌شده، موانع و خروج سفر را می‌بیند. والد روایت نوشتاری شامل تشخیص هدف، تصمیم درست، خطاها، زنجیره، سرعت و روند جلسات هم‌شرایط و نمودار فرزند خودش را می‌بیند. نمودار بر اساس همان جلسهٔ انتخاب‌شده است و فقط بازی، سطح، حالت، نوع جلسه، پروتکل، روش بازخورد، خانوادهٔ محرک شکار و نسخهٔ ترسیم محرک یکسان را مقایسه می‌کند؛ ارزیابی قدیمیِ پیوسته با ارزیابی دارای مرور و حروف قدیمی با ترسیم تازه مخلوط نمی‌شوند. گزارش از نتیجهٔ بازی، دقیقاً همان جلسه را باز می‌کند.

میانگین واکنش از آغاز محرک در بازی واکنشی، آغاز صفحهٔ جست‌وجو در جست‌وجو و تصمیم قبلی یا کناررفتن مانع در سفر محاسبه می‌شود. بدون انتخاب درست، مقدار میانگین `null` است. دقت برابر تصمیم‌های درست تقسیم بر همهٔ تصمیم‌های ثبت‌شده است.

PDF از پنجرهٔ چاپ مرورگر ذخیره می‌شود. JSON پرونده و CSV پاسخ‌ها فقط با مجوز سرور برای مدیر و درمانگر مسئول دریافت می‌شوند. والد به این خروجی‌های خام دسترسی ندارد.

## انتقال نسخهٔ محلی

در «حساب و دسترسی‌ها»، فایل JSON قبلی یا داده‌های همین مرورگر را بررسی کنید. پیش‌نمایش، تعداد نتیجه‌ها و خطاها را نشان می‌دهد. برای هر پرونده، ساخت پروندهٔ جدید یا ادغام با پروندهٔ مجاز موجود و درمانگر مقصد مشخص می‌شود. فایل نامعتبر ثبت نمی‌شود و ثبت معتبر یک تراکنش است.

دادهٔ قدیمی از مرورگر خودکار بارگذاری یا حذف نمی‌شود. شناسهٔ منبع به‌صورت `legacyId` و تاریخ و نسخهٔ پروتکل اصلی حفظ می‌شوند؛ شناسهٔ جدید سروری برای اتصال‌ها استفاده می‌شود. انتقال دوبارهٔ همان داده، پرونده یا نتیجهٔ تکراری نمی‌سازد. رکوردهای بدون پرونده خودکار به کودکی نسبت داده نمی‌شوند. نتیجه‌های واردشده با نسخه‌های متفاوت در نمودار مخلوط نمی‌شوند و سطح ثابت موجود را تغییر نمی‌دهند.

## APIها و توسعه

همهٔ مسیرها زیر `/api` هستند. `GET /auth/session` کاربر و توکن CSRF را برمی‌گرداند؛ تغییرات هدر `X-CSRF-Token` می‌خواهند.

- `/auth/login`، `/auth/logout`، `/auth/change-password`؛ `/invitations`، `/invitations/inspect` و `/invitations/accept`.
- `/users` برای مدیریت مجاز کاربران؛ `/children` و `/children/:id` برای پرونده.
- `/children/:id/parents` برای اتصال‌های والد؛ `/sessions` برای آغاز و سابقه و `/sessions/:sessionId/complete` برای ثبت یکتای پایان.
- `/children/:id/assessment`، `/difficulty` و `/reports` برای ارزیابی، سیاست سطح و گزارش.
- `/children/:id/export` و `/sessions/:sessionId/export` برای خروجی مجاز.
- `/imports/preview` و `/imports/commit` برای انتقال بازبینی‌شده؛ `/bootstrap` برای دریافت اطلاعات مجاز رابط.

اجرای Node بیرون Docker با پایگاه دادهٔ محلی:

```sh
npm ci
npm run setup:env
docker compose -f compose.yaml -f compose.dev.yaml up -d --wait db
npm run db:migrate
npm run build
npm start
```

فقط `compose.dev.yaml` پورت پایگاه داده را روی `127.0.0.1:55432` باز می‌کند. سرور Node و کانتینر app را هم‌زمان روی یک پورت اجرا نکنید. فرمان `npm run static` فقط فایل‌ها را میزبانی می‌کند و جای سرور چندکاربره را نمی‌گیرد.

```sh
npm test
npm run test:api
npm run test:e2e
docker compose build app
npm run test:docker
```

آزمون‌های اصلی بازی و رابط به پایگاه داده نیاز ندارند و API در آن‌ها شبیه‌سازی می‌شود. آزمون API با `.env`، پایگاه‌های موقت جدا می‌سازد و پاک می‌کند؛ کاربر اتصال آزمون باید اجازهٔ ساخت پایگاه داده داشته باشد. آزمون مرورگر از Chrome نصب‌شده استفاده می‌کند؛ مسیر آن با `CHROME_BIN` قابل تغییر است. Playwright مرکز، دو درمانگر و دو خانوادهٔ آزمایشی را در پایگاه مستقل می‌سازد و ارزیابی هفت بازی، انتقال بین دستگاه، دعوت، گزارش، محدودیت والد، بازی دوهدفه و بازیابی پس از قطع ارتباط را بررسی می‌کند. اجرای کامل هر هفت بازی اصلی و صفحهٔ آمادگی و محیط بازی در عرض‌های ۳۶۰، ۷۶۸ و ۱۴۴۰ پیکسل نیز آزموده می‌شود؛ تصویرهای آزمون در `.local/verification` ذخیره می‌شوند. آزمون‌های منطق و رابط، حذف زمان مرور و شمارش معکوس، توقف با تعویض زبانه، مرجع حافظه، انتخاب مزاحم و کنترل با صفحه‌کلید را پوشش می‌دهند.

`test:docker` پروژه و volume موقت خودش را می‌سازد، حساب اولیه، ثبت نتیجه، راه‌اندازی مجدد app/db و پشتیبان‌گیری و بازیابی را بررسی می‌کند و فقط داده‌های همان پروژهٔ آزمایشی را پاک می‌کند. هیچ آزمونی پایگاه اصلی `havaas` را خالی نمی‌کند.

## پشتیبان‌گیری و بازیابی

پایگاه داده در volume پایدار PostgreSQL است. برای تهیهٔ نسخهٔ پشتیبان، از ابزار داخل همان نسخهٔ PostgreSQL استفاده کنید:

```sh
mkdir -p backups
docker compose exec -T db pg_dump -U havaas -d havaas -Fc --no-owner > backups/havaas.dump
```

فایل پشتیبان شامل اطلاعات پرونده‌ها و کاربران است و باید در محل مجاز مرکز نگهداری شود. برای بازیابی کامل، app را متوقف و یک نسخهٔ پشتیبان از وضعیت موجود تهیه کنید؛ دستور زیر داده‌های پایگاه مقصد را جایگزین می‌کند:

```sh
docker compose stop app
docker compose exec -T db pg_restore -U havaas -d havaas --clean --if-exists --no-owner < backups/havaas.dump
docker compose up -d --wait app
```

در آزمون Docker، بازیابی در پایگاه جدا انجام می‌شود و تعداد و وجود جلسات بازی تأیید می‌شود. حذف volume با `down -v` دادهٔ مرکز را پاک می‌کند؛ برای توقف معمول از `docker compose stop` یا `docker compose down` استفاده کنید.
